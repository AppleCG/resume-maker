## 技术栈

- **后端**: Go, Gin, gRPC
- **前端**: React, TypeScript
- **数据库**: MySQL → TiDB 迁移, Redis
- **基础设施**: Kubernetes, Kafka, Prometheus, Grafana
- **其他**: 领域驱动设计(DDD), 事件溯源

## 项目概述

将单体 PHP 电商系统重构为 Go 微服务架构。旧系统在促销高峰期间频繁宕机，且代码耦合严重导致每次迭代周期超过3周。重构后系统支撑了双11期间200万DAU的平稳运行。

## 背景 & 挑战

- 原系统为 PHP 单体应用，代码超过50万行，耦合严重，新人上手需3个月
- 大促期间（双11、618）QPS峰值达到3万，经常触发限流和宕机
- 数据库 MySQL 单点瓶颈，订单表超2亿行，查询缓慢
- 业务方要求重构期间不停服，新旧系统逐步切换
- 团队人力有限，5个月内必须完成核心链路

## 我的工作

1. 主导微服务拆分方案设计，将单体拆为订单、商品、库存、支付、用户 5 个核心服务
2. 设计灰度迁移策略——API 网关按用户ID哈希逐步切流，新老系统并行运行2个月，实现零宕机迁移
3. 选型 TiDB 替换 MySQL，解决订单表水平扩展问题；设计分库分表方案，按用户ID分区
4. 引入 Kafka 实现订单事件的异步解耦：下单→扣库存→发券→通知，端到端延迟从 800ms 降到 120ms
5. 搭建全链路压测体系（JMeter + Prometheus + Grafana），提前发现并修复 7 个潜在瓶颈点

## 成果

- 系统可用性从 99.5% 提升到 99.95%，双11期间零宕机
- QPS 上限从 1.5万 提升到 5万，支撑 200万 DAU
- 订单查询 P99 延迟从 2.3s 降到 180ms
- 月度基础设施成本降低 35%（从 8.2万/月 降到 5.3万/月）
- 功能迭代周期从 3周 缩短到 1周
